# 1. 모든 클래스를 매번 한 번에 학습해야 하는 이유

## 처음 한 것

잘 되던 8종 모델(포트홀, 크랙, 차선 등)이 있었다.
2·3·4번(중앙분리대, 시선유도봉, 볼라드 파손)이 약해서, 이 세 클래스 사진만 모아
기존 `best.pt`에 추가 학습시켰다.

## 결과

추가 학습 후 **같은 영상에서 포트홀 검출이 87개 → 0개**가 됐다.
모델이 원래 알던 것을 잊어버린 것이다. 이걸 *catastrophic forgetting(파괴적 망각)* 이라고 부른다.

## 왜 그런가

- **학습은 보여준 데이터 쪽으로만 가중치를 움직인다.**
  새 데이터에 포트홀이 하나도 없으면 포트홀 가중치를 지켜줄 것이 없고, 매 업데이트마다 덮어써진다.
- **라벨 없는 물체는 배경으로 학습된다.**
  YOLO는 박스가 없는 곳을 전부 "물체 아님"으로 배운다.
  볼라드 사진에 포트홀이 찍혀 있는데 포트홀 라벨이 없으면, 모델은 *이건 포트홀이 아니다* 라고 배운다.
  기존 클래스를 적극적으로 반대로 학습하는 것이다.
- **클래스 번호는 자리일 뿐이다.**
  새 `data.yaml`의 클래스 순서나 개수가 다르면, 새 라벨의 0번이 기존 모델의 0번과 다른 뜻이 되고
  출력층이 새 뜻으로 다시 학습된다.

## 대신 이렇게 한다

1. **모든 클래스가 들어 있는 master 데이터셋 하나**를 두고, 매번 전체로 다시 학습한다
   (`yolo11n.pt`에서 시작하든 이전 best에서 시작하든, 데이터는 항상 전체).
2. **클래스 목록을 고정하고 번호를 절대 바꾸지 않는다.** 새 데이터셋은 모두 이 번호로 변환한다.
3. **사진에 보이는 클래스는 전부 라벨링한다.** 다른 클래스를 위해 모은 사진이어도 마찬가지다.
4. **따로 학습하지 말고 균형을 맞춘다.**
   - 많은 클래스는 클래스당 1,500~2,000장 정도로 제한
   - 적은 클래스는 `train`에서만 2~5배 반복 (`val`에는 원본만)
   - 박스 없는 배경 사진을 약 10% 넣기
5. **클래스별 val을 고정**해서, 어떤 클래스가 나빠졌는지 바로 보이게 한다.

받은 원본 데이터셋은 그대로 두고, 스크립트로 `train/`, `val/`을 매번 다시 만든다.
그래야 번호 변환과 반복 횟수가 매번 똑같이 적용된다.

## 새 데이터로만 추가 학습하면 절대 안 되나?

추가 학습 데이터에 기존 클래스도 들어 있다면 괜찮다 (예: 기존 데이터 일부를 섞기).
새 클래스만으로 학습하면 거의 항상 기존 클래스가 나빠진다.
